Resource Planning & Profit Modelling
The Complete Blueprint

From raw materials to powder to sachets to cartons to profit — every formula, every database field, every screen, every integration point, and the exact 8-week plan to deliver it. Written so the Plant Manager, Finance, HR, and the development team all read the same truth.

For: Plant Manager, Finance, COO, Development Team 7 live SKUs Firestore schema included 8-week roadmap Read time: ~15 minutes

01 The one-minute version

You put raw materials in. You get detergent powder out. You pack that powder into sachets of 7 different sizes. You put sachets in cartons. You sell the cartons. This feature tells you — for every Naira you spend on raw materials — how many kilograms of powder, how many sachets of each size, how many cartons, how much revenue, how much cost, and how much profit you get back.

📥 Input

Raw material budget (₦) OR target powder output (kg). Packing plan sliders for 7 SKUs. Ingredient price overrides.

📦 Throughput

Standard recipe (BOM) with yield %. Powder split across 7 SKUs. Cartons calculated from live Gram Specs piecesPerCarton.

💰 Output

Sachets per SKU. Cartons per SKU. Revenue, cost, profit, margin. Profit per ₦1 raw material. Revenue per ₦1 raw material.

🔮 Power tools

What-if scenarios side-by-side. Actuals vs plan variance. PDF/Excel export. Weekly scheduled email to Plant Manager + Finance.

💡
The core principle

Every number in this feature is derived, never stored as a counter. Change the recipe, the prices, or the packing plan — and everything recalculates instantly. No drift. No stale caches. The math is pure; the database just remembers what you decided.

02 What the Plant Manager asked for

In his own words, translated into the spec.

1

"I put raw materials in"

Surfactants (LABSA, SLES), builders (Soda Ash, Zeolite), enzymes, fragrance, colour, fillers. Each has a cost per kg that Finance updates.

2

"I get detergent powder out"

Standard recipe (Bill of Materials) with fixed ratios per batch. Yield % accounts for dust loss, moisture, off-spec. One batch in → known kg powder out.

3

"I pack that powder into sachets"

7 SKUs in the system right now: 22g, 40g, 45g, 85g, 125g, 170g, 850g. Each has its own piecesPerCarton, packerBreakdown, and density range. Not all SKUs run every time — the Plant Manager chooses the mix.

4

"I put sachets in cartons"

Cartons = sachets ÷ piecesPerCarton (from Gram Specs). The Gram Specs are the single source of truth — already in System Config.

5

"I sell the cartons"

Each SKU has a selling price per carton and a carton cost (packaging materials). Revenue = cartons × sell price. Cost = raw materials + packaging + conversion (₦/kg powder for power, labour, maintenance).

6

"Tell me the profit"

Profit = Revenue − Cost. Margin % = Profit ÷ Revenue. The Plant Manager's KPIs: Profit per ₦1 raw material, Revenue per ₦1 raw material, Cartons per ₦1 raw material.

🎯
The flexibility requirement

Not all 7 SKUs run every time. The Plant Manager sets a packing plan — percentage split across the 7 SKUs that totals 100%. Example: "This week we run 40% 85g, 25% 22g, 20% 40g, 15% 850g, zero 45g/125g/170g." Next week the mix changes. The feature must handle any combination.

What each column means for planning

⚖️ Density Range

From QC string weight checks. Powder must fall in this range to be packed into this SKU. The feature uses this to validate: if your calculated powder density is 0.28 g/mL, it can go into 22g, 40g, 45g but NOT 85g (needs 0.24+).

📦 Pieces/Carton

Total sachets per carton = bagCount + freebieCount. This is the denominator: cartons = sachets ÷ piecesPerCarton.

🧵 Packer's Breakdown

How the packaging team physically counts sachets into cartons. Example: 27 strings × 6 pcs means 27 strings of 6 sachets each = 162. This goes on the printed packing instruction sheet.

🔢 Bag vs Freebie

Bags are standard sachets. Freebies are extras. Both count in piecesPerCarton. Useful for cost modelling if freebie packaging differs.

🔗
The "bridging quantity" concept

Powder (kg) is the only number that connects the raw material side to the packaging side. Raw materials → Recipe → Powder. Powder → Packing Plan → Sachets → Cartons. If you change the recipe yield, powder changes, and everything downstream recalculates. If you change the packing plan, powder stays the same but sachets/cartons shift.

05 The mathematics — formulas in plain English

Every formula the feature runs. Written so a non-technical person can follow, and a developer can implement.

services/resourcePlanning.ts — pure calculation engine (no Firebase)
// ============================================================
// STEP 1: RAW MATERIAL COST
// ============================================================
interface IngredientInput {
  id: string;           // "LABSA", "SLES", "SODA_ASH", etc.
  name: string;
  kgPerBatch: number;
  pricePerKg: number;       // from ingredientPrices in config
}

function calculateRawMaterialCost(ingredients: IngredientInput[]) {
  return ingredients.reduce((sum, ing) => sum + ing.kgPerBatch * ing.pricePerKg, 0);
}

// ============================================================
// STEP 2: POWDER FROM RECIPE (THE BRIDGING QUANTITY)
// ============================================================
interface Recipe {
  name: string;
  yieldPercent: number;     // e.g., 86.9
  batchInputKg: number;       // sum of all kgPerBatch
  batchOutputKg: number;      // powder out per batch
  ingredients: IngredientInput[];
}

function calculatePowderKg(
  recipe: Recipe,
  inputMode: 'rawMaterialBudget' | 'targetPowderKg',
  inputValue: number
): number {
  if (inputMode === 'targetPowderKg') return inputValue;

  // inputMode === 'rawMaterialBudget'
  const totalRawCost = calculateRawMaterialCost(recipe.ingredients);
  const totalInputKg = recipe.ingredients.reduce((sum, ing) => sum + ing.kgPerBatch, 0);
  const batches = inputValue / totalRawCost;       // how many batches the budget buys
  return batches * recipe.batchOutputKg;         // powder kg = batches × output per batch
}

// ============================================================
// STEP 3: SACHETS FROM POWDER (7 SKUs, FLEXIBLE % SPLIT)
// ============================================================
type SkuId = '22' | '40' | '45' | '85' | '125' | '170' | '850';

interface PackingPlan {
  22: number;   // percentage, e.g., 40
  40: number;
  45: number;
  85: number;
  125: number;
  170: number;
  850: number;
  // sum MUST equal 100
}

interface GramSpec {
  piecesPerCarton: number;
  packerBreakdown: string;
  bagCount: number;
  freebieCount: number;
  minDensity: number;
  maxDensity: number;
}

function calculateSachetsAndCartons(
  powderKg: number,
  packingPlan: PackingPlan,
  gramSpecs: Record,
  powderDensity: number  // from QC density test
) {
  const skuIds: SkuId[] = ['22', '40', '45', '85', '125', '170', '850'];
  const results: Recordany> = {} as any;

  let totalSachets = 0;
  let totalCartons = 0;

  for (const sku of skuIds) {
    const pct = packingPlan[sku];
    if (pct === 0) {
      results[sku] = { sachets: 0, cartons: 0, powderKg: 0 };
      continue;
    }

    const spec = gramSpecs[sku];
    const skuGrams = parseInt(sku, 10);

    // Density validation: can this powder density go into this SKU?
    const densityOk = powderDensity >= spec.minDensity && powderDensity <= spec.maxDensity;

    const powderForSku = powderKg * (pct / 100);
    const sachets = Math.floor((powderForSku * 1000) / skuGrams);
    const cartons = sachets / spec.piecesPerCarton;

    results[sku] = {
      percentage: pct,
      powderKg: powderForSku,
      sachets,
      cartons,
      piecesPerCarton: spec.piecesPerCarton,
      packerBreakdown: spec.packerBreakdown,
      densityValid: densityOk,
      skuGrams
    };

    totalSachets += sachets;
    totalCartons += cartons;
  }

  return { skus: results, totalSachets, totalCartons };
}

// ============================================================
// STEP 4: REVENUE, COST, PROFIT
// ============================================================
interface SkuPricing {
  sellingPricePerCarton: number;
  cartonCost: number;
}

function calculateFinancials(
  skuResults: ReturnType<typeof calculateSachetsAndCartons>['skus'>,
  skuPricing: Record,
  totalRawCost: number,
  powderKg: number,
  conversionCostPerKg: number
) {
  let totalRevenue = 0;
  let totalPackagingCost = 0;
  const skuFinancials: Recordany> = {} as any;

  for (const [sku, data] of Object.entries(skuResults)) {
    const pricing = skuPricing[sku as SkuId];
    const cartons = data.cartons;
    const revenue = cartons * pricing.sellingPricePerCarton;
    const packagingCost = cartons * pricing.cartonCost;

    skuFinancials[sku as SkuId] = {
      cartons,
      revenue,
      packagingCost,
      profit: revenue - packagingCost,
      marginPercent: cartons > 0 ? ((revenue - packagingCost) / revenue) * 100 : 0
    };

    totalRevenue += revenue;
    totalPackagingCost += packagingCost;
  }

  const conversionCost = powderKg * conversionCostPerKg;
  const totalCost = totalRawCost + totalPackagingCost + conversionCost;
  const profit = totalRevenue - totalCost;
  const marginPercent = totalRevenue > 0 ? (profit / totalRevenue) * 100 : 0;

  // Plant Manager's KPIs
  const profitPerNairaRaw = totalRawCost > 0 ? profit / totalRawCost : 0;
  const revenuePerNairaRaw = totalRawCost > 0 ? totalRevenue / totalRawCost : 0;
  const cartonsPerNairaRaw = totalRawCost > 0 ? Object.values(skuResults).reduce((sum, d) => sum + d.cartons, 0) / totalRawCost : 0;

  return {
    totalRevenue,
    totalRawCost,
    totalPackagingCost,
    conversionCost,
    totalCost,
    profit,
    marginPercent,
    profitPerNairaRaw,
    revenuePerNairaRaw,
    cartonsPerNairaRaw,
    skuFinancials
  };
}

// ============================================================
// ORCHESTRATOR — ONE CALL DOES IT ALL
// ============================================================
interface PlanInput {
  recipe: Recipe;
  inputMode: 'rawMaterialBudget' | 'targetPowderKg';
  inputValue: number;
  packingPlan: PackingPlan;
  gramSpecs: Record;
  skuPricing: Record;
  powderDensity: number;           // from latest QC test
  conversionCostPerKg: number;
}

function runResourcePlan(input: PlanInput) {
  const totalRawCost = calculateRawMaterialCost(input.recipe.ingredients);
  const powderKg = calculatePowderKg(input.recipe, input.inputMode, input.inputValue);
  const sachetsAndCartons = calculateSachetsAndCartons(
    powderKg, input.packingPlan, input.gramSpecs, input.powderDensity
  );
  const financials = calculateFinancials(
    sachetsAndCartons.skus, input.skuPricing, totalRawCost, powderKg, input.conversionCostPerKg
  );

  return {
    powderKg,
    totalRawCost,
    skus: sachetsAndCartons.skus,
    totalSachets: sachetsAndCartons.totalSachets,
    totalCartons: sachetsAndCartons.totalCartons,
    financials
  };
}
🧪
Pure functions = testable, portable, auditable

The entire engine lives in src/services/resourcePlanning.ts with zero Firebase imports. Input: plain objects. Output: plain objects. Every function has unit tests. The UI just calls runResourcePlan(input) and displays the result. This is how you build features that never drift.

The density validation saved us

In this example, powder density was 0.285 g/mL. That's valid for 22g (0.200–0.310), 40g (0.200–0.310), 45g (0.210–0.310), 85g (0.240–0.300) but NOT for 125g (0.200–0.270), 170g (0.200–0.270), or 850g (0.200–0.270). The feature flags this automatically — the Plant Manager sees which SKUs are "density valid" for the current powder quality.

READS piecesPerCarton, packerBreakdown, min, max, bagCount, freebieCount for all 7 SKUs. Single source of truth — already live.

READS latest powder density from qc_tests (shift tests). Auto-fills the density input. WRITES actuals to actuals_runs for variance.
